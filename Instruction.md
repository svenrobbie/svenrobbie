# PART I — PROJECT FOUNDATION

## 1. Project vision

GURZÛL KHAR is an independent constructed language inspired by Tolkien's Black Speech and the linguistic atmosphere of Mordor.

The project aims to develop a complete, internally consistent language with its own:

- Phonology.
- Alphabet and writing system.
- Pronunciation conventions.
- Vocabulary.
- Grammar.
- Morphology.
- Syntax.
- Semantics.
- Word formation.
- Idioms and expressions.
- Historical development.
- Educational resources.

The project must also produce a complete public website where anyone can learn, read, write, speak and translate Gurzûl Khar.

The language must be usable beyond isolated words and short fantasy phrases.

It must support meaningful sentences, conversations, descriptions, questions, commands and increasingly complex written communication.

## 2. Language identity and fictional lore

### 2.1 Name

GURZÛL KHAR.

This is the official name of the language and project.

The name is a coined project identity and is not claimed to be an authentic Tolkien expression.

### 2.2 Fictional background

Within the project's fictional lore, Gurzûl Khar is a regional and historical dialect of Black Speech associated with Mordor.

It developed its own linguistic characteristics over time.

Its fictional history should explain:

- Where the dialect originated.
- Which populations used it.
- How it developed from the broader Black Speech linguistic tradition.
- Why its pronunciation and vocabulary differ.
- How its writing system emerged.
- How it was used in everyday life, administration, military communication and cultural expression.

The lore should support the linguistic design rather than dictate arbitrary grammatical rules.

### 2.3 Real-world identity

In reality, GURZÛL KHAR is an independent fan-created constructed language.

It is inspired by Tolkien's linguistic world but has its own original linguistic system.

The project must not claim official status, authorship by Tolkien or endorsement by rights holders.

- IPA symbol.

- Place of articulation.
- Manner of articulation.
- Voicing.
- Example words.
- Pronunciation instructions.
- Whether it can occur at the beginning, middle or end of a word.

### 3.4 Stress and intonation

# PART IV — LANGUAGE ENGINE

## 7. Deterministic translation system

Build a real language processing engine.

The translator must not merely replace words in a dictionary.

It must understand and apply the grammar.

### 7.1 Supported translation directions

Implement all four directions:

1. English → Gurzûl Khar.
2. Dutch → Gurzûl Khar.
3. Gurzûl Khar → English.
4. Gurzûl Khar → Dutch.

### 7.2 Translation process

The engine should perform:

1. Language identification.
2. Input normalisation.
3. Tokenisation.
4. Morphological analysis.
5. Semantic interpretation.
6. Lexical lookup.
7. Grammatical transformation.
8. Word formation.
9. Sentence construction.
10. Orthographic rendering.
11. Output generation.

### 7.3 Unknown vocabulary

When a word does not exist:

- Analyse its meaning.
- Search for related concepts.
- Check existing roots.
- Apply documented derivational rules.
- Generate a candidate where justified.
- Validate the candidate.
- Explain its construction.
- Mark it as newly created.

Do not silently create arbitrary words.

### 7.4 Consistency

The engine must be deterministic.

Identical inputs and identical language versions must always produce identical outputs.

### 7.5 Translation explanation

Every translation should optionally provide:

- Original input.
- Result.
- Word-by-word analysis.
- Root identification.
- Grammatical transformations.
- Pronunciation.
- Native script.
- Confidence or completeness information.

### 7.6 Reverse translation

Support morphological parsing and grammatical interpretation.

If a sentence has multiple interpretations, present alternatives.

Never claim a degree of accuracy that the actual language system does not support.

# PART VIII — PROJECT QUALITY AND GOVERNANCE

## 17. Linguistic design principles

The following rules are mandatory:

1. Gurzûl Khar is its own language.
2. Its inspiration is Black Speech, not a requirement to reproduce Black Speech exactly.
3. The language must be internally consistent.
4. Every grammatical rule must be documented.
5. Every word must follow the language's phonological rules.
6. Word creation must be systematic.
7. The alphabet must represent the actual sound system.
8. Pronunciation and spelling must agree.
9. The same grammar must be used throughout the translator and learning course.
10. All important linguistic decisions must be version-controlled.

## 18. AI autonomy

The AI is authorised to make original linguistic and technical design decisions necessary to complete the project.

It should not ask the project owner to approve every individual word, letter or grammatical rule.

Instead:

- Make coherent design decisions.
- Document the reasoning.
- Record alternatives considered.
- Explain significant trade-offs.
- Maintain a design-decision log.
- Keep the entire language internally consistent.

Ask for user input only when a decision materially changes the project's direction, identity or fundamental design.

## 19. Copyright and independence

The project must remain an independent fan-made creation.

Use existing Black Speech material as inspiration and research context.

Do not reproduce copyrighted source material unnecessarily.

Create original:

- Vocabulary.
- Grammar.
- Alphabet artwork.
- Font assets.
- Logo.
- Educational explanations.
- Example texts.
- Website design.

Clearly distinguish original project content from references to third-party material.

Choose appropriate licences for software, documentation, artwork and original linguistic datasets.
